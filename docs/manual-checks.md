# 实机验收表

记录客户端版本、系统版本、当前 build、测试时间和结果；不要提交机场 URL 或凭证。
本地代码测试没有替代以下检查。

## 三个平台共同检查

1. 导入机场 A，应用统一配置，确认 24 个组及初始 15 条个人规则。
2. 在手动组查看具体节点，确认“剩余流量”“套餐到期”“reset”“Expiry”等节点没有进入任何节点池组。
3. 检查 HK/TW/JP/SG/US/EU/其他地区。缺少地区节点时记录空组，不把空组测速或直连当成地区出口验证成功。
4. 进入 OpenAI/Gemini/Telegram 等组，确认展示上层组，苹果/微软允许默认全局直连。
5. 打开 github、dnscheck.tools、ippure、joox、blinkroom，检查规则与目标。关闭旧连接后重试。
6. 检查 `api.openai.com`、一个国内网站、未命中的域名与个人 IP `18.162.180.119`。
7. 在 GitHub 把 github 的目标临时改成日本，完成发布、客户端下载、重新应用；确认新连接选中日本组。
8. 导入机场 B 并切换，确认新节点动态进入组；删除 A，确认没有悬空的固定节点引用。
9. 记录本地原 DNS 设置，再应用新脚本/配置，核对实际运行配置。本项目不要求修改 DNS。

## Windows

确认使用的是全局扩展脚本，并检查订阅后置扩展没有覆盖它。
运行同步工具，确认 `.js.bak` 出现、首行 build 改变，再重新应用当前配置。
在连接详情检查规则及组；单看脚本下载成功不算通过。
用错误 URL 或中断下载，确认旧脚本/旧连接仍可恢复使用。

## Android

记录 FlClash 版本与远程脚本 URL；确认新机场关联的是同一个脚本资源。
开启资源自动更新，记录间隔；先手动同步验证重载路径，再让应用运行跨过到期时间，检查脚本版本与连接日志。
分别测试应用前台、后台及系统省电状态。若被杀后不能更新，记录系统限制，不写成自动更新通过。

## iOS

1. 使用生成 `.conf` 后确认手动/地区组能取到首页订阅节点。若为空，核对组的订阅开关及服务器节点选择。
2. 打开规则集 URL 列表，确认除纯进程 applications 的说明外，所有实际引用列表下载成功，再使用/编译。
3. 在“测试规则”中输入样例，检查第三字段目标；特别比较个人 IP 与后续域名规则冲突时的编译后顺序。
4. 对香港/日本正则测试机场实际命名，确认假节点被排除；记录不存在地区的空组处理。
5. 确认自动/故障转移/负载均衡的测速地址、间隔、超时和实际出口；在禁用一个测试节点后观察切换时序。
6. 后台 App 刷新开启后等待真实配置更新，检查首行 build 及编译后的连接目标。手动更新作为恢复路径。
7. 原配置有 DNS 自定义时，验证本地包含配置的继承关系；生成文件本身应只有 update-url 这一 General 配置。
8. 更换机场、重新下载远程配置后再次检查组是否仍能引用节点，是否需要恢复本地的订阅关联。

## 回滚

从 release 历史版本恢复文件并发布新的恢复提交，按各客户端方式更新和重载。
确认 build 回到目标版本、个人规则目标恢复、旧规则快照仍能读取，再恢复原定时发布设置。
